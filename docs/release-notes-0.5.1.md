# Overcode 0.5.1 Release Notes

0.5.1 adds two new agent backends — OpenAI's Codex CLI and xAI's Grok Build — bringing overcode's supported CLIs to four: Claude Code, opencode, Codex, and Grok. It also closes out a piece of unfinished business from opencode support: bypass mode now genuinely bypasses opencode's permission rules instead of quietly behaving like permissive mode.

## Codex CLI support

Launch a codex agent with `overcode launch -n my-agent --backend codex` (or `-B codex`). Everything you'd expect from a full backend works: launch, restart, revive, resume (`codex resume <id>`), fork (`codex fork <id>`), kill, send-instruction, and hooks-grade live status — including the `waiting_approval` distinction pane polling alone can't make. Every launch injects `overcode hook-handler` via per-launch `-c 'hooks.<Event>=[...]'` config overrides plus `--dangerously-bypass-hook-trust`, so nothing is written to your project or to `~/.codex/config.toml`.

Token and context columns read codex's own rollout JSONL (`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`) accurately. Cost is a **list-price estimate**, not a billed figure — codex is subscription/API billed with no local per-turn charge to compare against, but `pricing.py` now carries an entry for `gpt-5.6-sol` (codex's account-default model), sourced from OpenAI's own pricing docs, so the estimate uses codex's real published rate instead of falling back to your configured default model's rate.

Two gestures worth knowing if you supervise a codex agent by hand: bare `C-c` **kills codex instantly, with no confirmation** — never send it; the safe interrupt is a single `Escape`. Clear-conversation is `/new`, not `/clear`; graceful exit is `/quit` or `/exit`.

## Grok Build support

Launch a grok agent with `overcode launch -n my-agent --backend grok` (or `-B grok`). Same launch/restart/resume/fork/kill/hooks-grade-status story as codex, plus two capabilities unique to grok among overcode's non-Claude backends: **session-id prescription** (overcode mints the uuid and grok lands the session at a predictable path) and a **permission allowlist** (`--allowed-tools` becomes repeated `--allow <rule>` flags that actually suppress the approval dialog). Grok also mints and eagerly binds a brand-new prescribed session id on fork rather than discovering one after the fact — as of the #466 fix below, Claude Code forks now take the same eager-binding path.

Grok's token/cost/context columns are the most complete of any non-Claude backend: `GrokStatsReader` reads a full, genuinely billing-accurate split from `updates.jsonl`'s `turn_completed.usage` — not an estimate. Two things had to be corrected empirically before that reader could be trusted: usage objects are per-turn, not cumulative, so overcode sums them rather than taking the latest one; and `costUsdTicks` is nano-dollars (1e9 per USD), not the coarser scale an early sample hadn't ruled out.

Grok requires a SuperGrok or X Premium+ subscription and a one-time `grok login` outside overcode. If `~/.grok/auth.json` is missing or empty, `overcode doctor` now names `grok login` explicitly instead of letting the launch fail with no explanation.

Bare `C-c` is **safe** on grok (interrupts only, session stays alive) — the opposite of codex and opencode. Clear-conversation is `/new`; approve/reject are bare digit keys (`2`/`3`, no Enter) — the default-selected dialog option is *always-approve*, not a one-time approval, so `overcode send approve` deliberately sends `2`, never a bare Enter.

## opencode: bypass mode is a real bypass now

Previously, overcode's `permissive` and `bypass` modes both mapped onto opencode's single `--auto` flag, and `--auto` leaves opencode's own `"deny"` rules in force — so bypass mode quietly behaved like permissive, not like Claude's `--dangerously-skip-permissions`. As of 0.5.1, **bypass** mode additionally sets `OPENCODE_PERMISSION` to an allow-everything JSON blob, which is merged into opencode's resolved config *after* project config and genuinely overrides `"deny"` rules — live-verified via `opencode debug config`. **permissive** mode is unchanged (`--auto` alone, deny rules still win). No file is written; the variable is process-scoped to the launched opencode process only.

## Devcontainer support for codex and grok

`--wrapper devcontainer` now recognizes `codex` and `grok` in `OVERCODE_BACKEND`. codex installs the same way Claude Code does (`npm i -g @openai/codex`); grok has no npm package and uses x.ai's own curl installer instead. `XAI_API_KEY` is now forwarded alongside the existing provider-credential list.

## Honest gaps

- **Codex's cost column is an estimate, not a bill.** codex has no local per-turn charge recorded anywhere, so even with the new `gpt-5.6-sol` pricing entry, the cost column is always a computed estimate — accurate only insofar as the entry's list price matches what you're actually billed (promotional pricing OpenAI has said runs through ~Nov 21, 2026; tiers other than standard/short-context aren't modelled).
- **Grok requires a subscription overcode cannot provision for you.** SuperGrok or X Premium+, plus a one-time `grok login` outside overcode. CI and most other machines will not have this — all of overcode's own tests run against a mock grok CLI.
- **Grok's devcontainer auth story is unverified, not confirmed unsupported.** No live docker build was run as part of this release (out of scope by design); `XAI_API_KEY` is forwarded, but whether grok's interactive subscription-login flow works from inside a container's tmux pane has not been tested.
- **Tested version ranges**: codex `>=0.148.0, <1.0.0` (ships multiple releases a week; `overcode doctor` warns outside this range and always flags codex's enabled-by-default in-app updates). grok `>=1.0.5, <2.0.0` (no fast-churning release cadence found, but the guardrail still applies as the corpus ages). opencode's tested range is unchanged at `>=1.18.0, <2.0.0`; the bypass-mode `OPENCODE_PERMISSION` verification specifically was re-run live against v1.18.23.

## Fixes

- **CTX% could show a wrong number for an unrecognized model, instead of "unknown" (#469).** `history_reader.model_context_window()` used to fall back to a 200K default for any model overcode didn't have metadata for, so the CTX column showed a plausible-looking but wrong percentage rather than a dash — reported against opencode + `gpt-5.6-sol`, where the real usage (11,822 tokens, 1% per opencode's own report) showed as 6% in the TUI (11822/200000 ≈ 5.9%, i.e. exactly the 200K-default math, not a real context-window calculation). A second bug compounded it: opencode's stats reader stores model ids qualified with a provider prefix (`"openai/gpt-5.6-sol"`), but the lookup table was keyed on the bare id, so an exact-match lookup missed *every* opencode model, including ones the table already had — now fixed generically by stripping the qualifier before lookup. Context-window metadata was also extended, each entry cited, for the model families actually reachable via opencode/codex/grok on this branch: the current OpenAI/codex family (`gpt-5.6-sol` and siblings — sourced from this machine's own real codex rollout data, which reports the figure directly), xAI Grok 4.5/4.6, Zhipu GLM-4.6, and Moonshot Kimi K2. An unrecognized model still renders a dash — that's the fix, not a wider table. Where codex's own transcript reports its session's real context window (it does, per-turn), overcode now prefers that live figure over the static table. See `docs/design/agent-backends-codex-grok.md`'s Post-0.5.1 hardening §5 for the full writeup, including a recommendation (not implemented) for sourcing this metadata from a maintained cross-model catalog like [models.dev](https://models.dev) instead of hand-curated entries.
- **Forking a Claude agent in a shared working directory could bind the wrong session id (#466).** Claude Code forks deliberately left their new session id unset at launch, relying on the monitor daemon to discover it afterward by matching `history.jsonl` entries against the fork's `start_directory` and launch time. That heuristic is ambiguous the moment another agent (parent, sibling, or an archived fork) shares the same directory — the "most recent session here" is frequently not the fork's own, so the fork's record could end up bound to a foreign session, and its tmux window would then show that foreign conversation. A live check found the assumption behind the old design was simply wrong: `claude --resume <id> --fork-session --session-id <new-uuid>` **does** honor a prescribed fork id — the fork's transcript is written under the new uuid, a full replay of the parent conversation plus the new turn. `ClaudeCodeBackend` now sets `fork_prescribes_new_session_id = True` (the same flag grok already used) and forks get their id minted and bound eagerly at launch, exactly like a fresh launch — no post-launch discovery, no ambiguity, regardless of how many other agents share the directory. Grok was already immune (it prescribes fork ids itself); codex was already immune (its `SessionStart` hook records the id directly). Claude Code is now immune the same way. The "wrong window" symptom the issue described was entirely downstream of the unbound id — with a correctly bound id, `--resume <source-id> --fork-session` replaying the source conversation is correct fork behavior, not a bug.
- **Unbounded growth of `agent_status_history.csv` and `diagnostics/event_loop_timing.csv` (#465, #468).** Both files grew without any rotation, retention, or size cap — one real devpod hit 2.4GB/21M rows on the status history and 3.7GB on the diagnostic timing file, contributing to a full disk. `agent_status_history.csv` is archival (it backs the TUI timeline, parquet export, and web analytics), so it's now rotated hourly to compressed `.csv.gz` archives once it exceeds 50MB or spans more than 7 days, with archives retained for 18 months (540 days) by default and the web dashboard's date-range analytics endpoint transparently reading them; the windowed TUI/export readers are unaffected since rotation never touches the most recent 30 hours. `diagnostics/event_loop_timing.csv` is diagnostic-only (the TUI's event-loop responsiveness probe), so it's simply hard-capped at 100MB with the oldest rows dropped, and can be disabled outright via config. `overcode doctor` now flags either file (or archive set) once it exceeds 5GB (sized above an intentional 18-month archive set). See [History Retention](configuration.md#history-retention) for the config knobs.

## Smaller changes

- `docs/backends.md`'s permission-modes section now describes opencode's bypass/permissive split honestly instead of noting they "collapse."
- A cross-backend sweep test (`tests/unit/test_cross_backend_sweep.py`) asserts the backend registry, BKD badges, the new-agent modal, and `overcode doctor` all handle a fleet mixing all four backends without a crash.
- `docs/architecture.md`'s Agent Backends section, `docs/README.md`, and the top-level `README.md` now name all four backends instead of two.
